# Catalyst deployment — catalyst (self-hosted)

This is catalyst's own instantiation of the catalyst framework — the
framework governing itself, dogfooding the same rule/artifact/work-item
chain it prescribes for every other project. Deployed via the retrofit
path (`development-framework/INSTANTIATION-GUIDE.md` §4): the project's
existing practice — its scripts, its tests, its already-documented
invariants — was extracted into real, ID'd rules rather than invented
from scratch.

## Structure

```
CODE-OF-CONDUCT.md      Dev-artifact standards, users/roles, slash commands (from
                         development-framework/rules-of-development.template.md)
rules/
  Rules-of-Rules.md      Meta-rules governing this deployment's rules
  rules.md                Global rule index
  TEMPLATE-RULE.md
  framework/
    fw-framework-rules.md  The one rule document — retrofitted from
                            development-framework/INVARIANTS.md
requirements/            REQ- docs (none yet)
features/                FEAT- entries (none yet)
domains/                 BEHAVIOR, STRUCTURE, PLUGINS domain files
development/
  bugs/, house-keeping/, meta-tags/   (none yet)
  BACKLOG.md              Regenerated by /show-backlog — never hand-edited
  roadmaps/                Named roadmaps (none yet — add one via /roadmap-add)
  users.json               Registered users — managed only by /user-*
  roles.json                Role → action mapping — managed by /role-add, /role-modify
work-items/               EPIC/STORY/TASK/SPIKE/SPRINT (none yet)
version.txt               0.7.1 — matches development-framework/version.txt
```

## Why one rule document

Catalyst's own repo has one natural seam — the framework itself — so
everything lives under a single `fw` prefix rather than splitting into
multiple rule documents. See `rules/Rules-of-Rules.md` §2.
